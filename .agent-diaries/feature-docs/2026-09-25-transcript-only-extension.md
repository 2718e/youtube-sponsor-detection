# Transcript-only extension

*2026-09-25*

## What changed

The extension used to have three modes — Transcript, Smart and Listen — and the
latter two captured the `<video>` element's audio, streamed 16 kHz PCM through
an offscreen document to Deepgram, and asked the model about what was heard.
All of that is removed. Transcript mode is the whole extension now.

Deleted: `extension/offscreen.{html,js}`, `extension/pcm-worklet.js`,
`src/live.js` and its `extension/lib/` copy, `test/live.test.js`.

Stripped from what remains:

- `background.js` — the eight `live-*` messages, the offscreen helpers, the
  audio port relay, the Deepgram settings and the five live counters.
- `content.js` — audio capture, the worklet, auto start/stop on play and pause,
  Smart mode's candidate windows, the audio line and the decision log.
- `popup.*` — the mode picker, the Deepgram key, the jump-step and speech-price
  fields, the Start/Stop listening button.

## What the extension does now

1. The content script asks the page for the current video's caption tracks
   (four routes, first one that answers wins).
2. The worker builds labelled transcript lines and runs the pipeline through
   the configured provider.
3. The panel lists each read with its range and confidence, offers Skip per
   read, auto-skips when the confidence clears the user's threshold, marks the
   reads on the progress bar, and toasts with an Undo that pauses auto-skip for
   that video.

## Consequences worth knowing

- **Permissions shrank to `storage`.** No `offscreen`, no `tabs` API, and no
  `web_accessible_resources` — nothing is loaded through
  `chrome.runtime.getURL` any more.
- **Firefox became cheap to support.** The offscreen document and audio capture
  were the only parts without a Firefox equivalent.
- **The retry/timeout surface is smaller.** One HTTP provider call, no
  long-lived socket to keep alive or reconnect.
- **Speech-to-text is gone from the project entirely**, so analysing a video
  needs a transcript and nothing else. YouTube replies with an empty caption
  file to some requests; the four routes exist for that.

## Not carried over

The README still documents the three modes and the audio screenshots still show
the old panel. Root `README.md` is deliberately untouched; this diary is the
current description. `docs/panel.png` and `docs/popup.png` are regenerated by
`npm run screenshots`, which needs Playwright's Chromium.
